## M1 でできること

- ホーム：3 軸ゲージ、体力バー、調子（好調/絶好調）、連続日数、週のお題、今週のランクと合計、今日の記録一覧。
- プロデュース開始：3 択（レッスン 2 枚 + 休む）。SP / お題バッジ。引き直し（1 日 2 回）。体力 0 なら「休む / 寝る」のみ。
- レッスン：タイマー。終了時に通知。中断も可（経過比例・最低 50%）。
- 自己申告：ちゃんとできた / 微妙 / 失敗。理由チップ。正直ボーナス。隠れて YouTube → 娯楽ログに自動追加。
- 休む：30 / 60 分（設定可）。終了時に通知。実時間で体力回復（30 以下 1.5 倍、80 以上は回復なし、1 日 +30 まで）。
- 後付け記録：「さっきやった」「娯楽してた」。前日分まで。
- 寝る宣言 / オフ日 / 起床時の睡眠申告（回復率に反映）。
- アクション管理：追加・編集・ON/OFF・論理削除。時間を選ぶとコスト・獲得の目安が自動入力。
- 設定：体力まわり、休む候補、引き直し回数、SP 率、日付境界、ランク閾値、軸の名前。
- 通信なし（`INTERNET` 権限なし）、バックアップ無効。

## M2 でできること（割り込み）

- 設定 → 割り込み → 「アクセシビリティ設定」で本アプリのサービスを ON にすると、対象アプリ（既定：YouTube / X / TikTok / Instagram。設定で追加・削除）を開いた瞬間に全画面の 3 択が出る。
- レッスン中に対象アプリを開くと「レッスン中！」で止め、脱線回数を記録（結果画面で確認を促す）。
- 「休む」を選ぶと許可時間だけ通し、時間切れで次に開いたときに休む終了処理をして再び 3 択。
- 静かな時間（既定 22〜5 時）、寝る宣言中、オフ日は割り込まない。
- 3 択画面を長押しで緊急バイパス（既定 5 分、1 日 3 回、記録に残る）。
- サービスの接続・切断を `service_gaps` に記録（レポートで「監視なし」表示に使う予定）。

## M3 / M4 でできること（レポート）

- 日次レポート：翌朝 5 時（または「寝る」宣言時）に自動生成して通知。獲得・体力・レッスン内訳・失敗理由・娯楽・バイパス・監視なし時間・コメント。
- 週次レポート：月曜 5 時に自動生成して通知。ランク S〜D、軸ごとの前週比、日別の棒グラフ、脱線率、ハイライト。
- 端末が落ちていた日は次に起動したときにバックフィル。レポート画面に「推移（30 日）/ 日次 / 週次」タブ。
- 生成は WorkManager（6 時間ごと ＋ 日付境界直後の 1 回）とアプリ起動時。

## M4.5 でできること（中期目標と試験）

- 目標を 1 つ置く（テンプレ 3 種 or 自作）。ターゲットは「軸の獲得量」「アクション回数」「チェック項目」を混在可、必須/加点を選べる。
- ホームの目標カードで残日数・進捗・「あと ゲーム制作 × 5 回」の逆算を常時表示。タップで詳細（抜き打ち試験）。
- 遅れている軸は 3 択の重みが ×2〜×3 になり「試験対策」バッジが付く。
- 週次レポート生成時に中間試験を記録、期限翌日に最終試験で合格/不合格を確定。不合格なら「同じ目標で再挑戦」。
- 体力の実現可能性チェック（必要体力が回復見込みの 8 割超なら警告）。

## レビューで直したこと（2026-11-01）

レビューは「ファインダー 10 観点 → 指摘ごとに反証 3 レンズ → 修正 → 修正差分を再レビュー」の流れ。主な修正：

- **休むとレッスンの排他**：休憩中にレッスンを始めると休むをそこで終える（回復確定）。レッスン中は休めない。割り込み判定もレッスン優先。
- **休むの追跡**：進行中の休むは `rest_logs` の未終了行で追う（日付境界をまたいでも終えられる）。期限切れの休むは次の操作時に自動で閉じ、休む終了アラームでも閉じる（`ProduceAlarmReceiver`）。
- **3 択の手札固定**：手札のシードを `day_states.choiceSeed` に保存。画面を閉じても割り込みが何度来ても同じ手札。引き直し回数の制限がちゃんと効く。レッスン完了・休む終了で新しい手札。
- **前日への書き込み**：後付け記録・境界をまたいだレッスン・ログ削除は、今日の行（体力・正直ボーナス）に伝搬し、その日のレポートを作り直す。バックフィルも前日分は毎回作り直す。
- **ログ削除**：「隠れて娯楽」で自動生成した娯楽ログも一緒に消し、正直ボーナスの状態を残りのログから再計算。
- **割り込み画面**：戻る操作で娯楽アプリに戻さない（ホームへ）。緊急バイパスは **画面のどこでも 3 秒長押し**（カードの上でも効く、進捗バー付き）。サービスの監視対象パッケージをブロック対象だけに絞る。死活監視の通知は「止まった瞬間 1 回 ＋ 6 時間に 1 回」まで、初回セットアップ前は鳴らさない。
- **レポート**：娯楽時間の定義を 1 つに統一（休む＋バイパス＋自己申告）。日次・週次に目標の要約・中間試験の判定・週のお題の達否を載せた。週をまたぐストリーク、失敗コメントの閾値、壊れた JSON での落ちを修正。
- **寝る**：3 択の「寝る」からも日次レポートを即生成して通知。確認ダイアログ付き。
- **ナビ**：戻る矢印の 2 度押しで画面が真っ黒になる問題、通知からの遷移が回転ごとに再送される問題を修正。
- **CI**：debug 署名鍵をキャッシュして、新しい APK を上書きインストールできるように（詳細は下記「ビルドの見方」）。
- **DB**：スキーマ v2（`rest_logs.actionLogId`、`day_states.choiceSeed`）。v1 からはマイグレーションで移行。
- ほかに、常駐のレッスン中通知（残り時間カウントダウン）、既定の対象アプリを全部外しても復活しない、設定値の範囲チェック、ワーカー / アラーム / バックアップ / 目標の原子性など多数。

## ビルドの見方

1. GitHub → Actions → "Android CI"。ブランチ `claude/idol-master-self-produce-app-zpkjs3` の最新 run を開く。
2. 成功していれば Artifacts に `produce-m-iself-debug-apk` がある。ダウンロードして Pixel に入れる（開発者オプションで USB デバッグ or ファイルから直接インストール）。
3. 手元で開くなら Android Studio でルートを開くだけ。JDK 17 以上。

署名鍵について：CI は debug 署名鍵を Actions のキャッシュに保存して使い回すので、2 回目以降の APK は前の APK の上にそのまま入る。
ただし **鍵キャッシュを入れた最初の run より前の APK** が入っている場合は、一度アンインストールが必要（設定 → バックアップでエクスポートしてから）。
Android Studio のビルドと CI のビルドで同じ鍵にしたいときは、手元の `~/.android/debug.keystore` を `base64 -w0` した文字列をリポジトリの secret `DEBUG_KEYSTORE_B64` に登録する（CI はそれがあれば優先して使う）。キャッシュは 7 日使われないと消えるので、長く使うなら secret の方が確実。

## 設計上の判断（SPEC に書いていない細部）

- 体力の現在値は `day_states.stamina` に持つ。ログを削除すると消費分を戻す。
- 「今日」は日付境界までの時間（最大 30 秒）ごとに再評価し、境界をまたぐとホームが自動で切り替わる。
- 調子（好調/絶好調）は「昨日までの連続日数 + 1」で判定して今日のレッスンに適用する。ホームの表示も同じ式。
- 週のお題は、中期目標で遅れている軸があればそれ、なければ `Random(weekStart)`。
- 休むの回復は終了時に実時間で計算（許可時間が上限）。終了は、休む終了アラーム・次の操作・割り込み判定のどこかで自動的に行われる。前日に始めた休むの回復は「終えた日」の体力に乗る。
- 正直ボーナスは次のレッスンまで持ち越す（間に何もしない日が挟まっても消えない）。
- 書き込みは `ProduceRepository` の Mutex（再入不可）で直列化。ロック中にウィジェット更新やレポート生成（homeState を読む）をしないこと。
