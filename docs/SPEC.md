# produce-m-iself 仕様書（v0.4 確定版）

> 学園アイドルマスター（学マス）のプロデュース感覚で、**自分自身をプロデュースする** Android アプリ。
> 娯楽アプリ（YouTube・ゲームなど）を開く前に割り込んで「3択」を出し、
> レッスン（自己成長）か「休む」（娯楽）かを選ばせる。選択結果はステータスと体力に反映され、
> 毎日・毎週レポートを自動生成する。
>
> - 利用者：自分だけ（外部リリースなし。GitHub は public のままでよい）
> - 状態：**M0 確定**。v0.1 の質問 8 件に回答済み（第 10 章）。v0.3 で中期目標と試験（第 12 章）、v0.4 で運用機能（第 13 章）とレッスン失敗（3.8）を追加。次は M1 実装。
> - 端末：Pixel（最新 Android）。開発は手元の Android Studio。

## 1. コンセプト

| 学マス | このアプリ |
|---|---|
| アイドル | 自分 |
| プロデューサー | アプリ（＋自分） |
| レッスン（Vo / Da / Vi） | 自己成長アクション（3カテゴリ） |
| 体力 | 1日の行動エネルギー（アクションで消費、休む・睡眠で回復） |
| 休む / お出かけ | 娯楽（YouTube・ゲーム等）。体力は回復するがステータスは上がらない |
| ターン | 1日 |
| 中間 / 最終試験 | **中期目標**に対する試験。週ごとに中間試験、期限に最終試験。足りない項目を逆算して表示（第 12 章） |
| 週の評価 | 週次レポートで獲得量ランク（S〜D）判定 |
| SP レッスン | ランダムに出現する獲得量 1.5 倍のアクション |
| 好調 / 絶好調 | 連続達成（ストリーク）による獲得量バフ |

**ゲームデザインの軸**

1. 「やらなきゃ」ではなく「どれ選ぶ？」。常に 3 択で、娯楽も正当な選択肢（休む）として用意する。
2. 体力に上限がある → 1 日に詰め込めない。無理すると翌日に響く。
3. 成長が数値とグラフで見える。レポートが毎日・毎週勝手に届く。
4. 中期目標を置くと「試験」が走り、何がどれだけ足りないかを逆算して 3 択にも反映される。

## 2. コアループ

```
[娯楽アプリを開こうとする]
        │ 割り込み（AccessibilityService で検知 → フルスクリーン表示）
        ▼
[3択画面] ── 2枚：レッスン（カテゴリ別・体力コスト・獲得量表示）
          └─ 1枚：休む（娯楽を N 分だけ許可・体力小回復）
        │
   ┌────┴─────┐
   ▼          ▼
[レッスン]   [休む]
 タイマー開始   娯楽アプリへ戻す
 終了時に完了   N 分後に再び割り込み
 ステータス↑    体力↑（上限あり）
 体力↓
        │
        ▼
[その日の終わり] 日次レポート自動生成 → 通知
[週の終わり]     週次レポート自動生成（ランク判定）→ 通知
```

割り込みなしでもホーム画面から自分で 3 択を引ける（「プロデュース開始」ボタン）。

## 3. ゲームシステム

### 3.1 ステータス（3 軸、名前は変更可）

| 学マス | 名前 | 色 | 例 |
|---|---|---|---|
| ダンス | **健康** | 赤 | 筋トレ、ランニング、ストレッチ、散歩、早寝 |
| ビジュアル | **趣味** | 黄 | ゲーム制作、イラスト制作、音楽、工作などの**能動的・創作系の趣味** |
| ボーカル | **自己実現** | 青 | 勉強、資格、コーディング、仕事のスキル、将来につながる作業 |

**「趣味」と「娯楽（休む）」の線引き**：自分で何かを作る・動かすのが「趣味」（ステータスが上がる）。
動画やゲームを見る・遊ぶ、SNS を眺めるのは「娯楽」（休む。体力は回復するがステータスは上がらない）。
迷ったら「終わったあとに成果物やログが残るか」で判定する。

- 軸の名前・色は設定で変更可。
- 各ステータスは 0 から積み上げ（上限なし、学マスの 1500 上限みたいなキャップは設けない）。
- 週次ランクは「その週の獲得量」で判定するので、途中から始めても不利にならない。

### 3.2 体力

| 項目 | デフォルト | 備考 |
|---|---|---|
| 最大体力 | 100 | 設定で変更可 |
| 1日の開始時 | 日付境界（朝 5:00）に **回復率 100%**（設定で 50〜100% に変更可、例 75%） | 回復率を下げると「前日の疲れが残る」モードになる。将来は Health Connect の睡眠時間で回復率を自動調整（第 11 章） |
| レッスン消費 | アクションごとに設定（小 10 / 中 20 / 大 30） | 目安：15分=小、30分=中、60分=大 |
| 休む（娯楽）回復 | +5 / 15 分（1 時間で +20）、1 日の娯楽回復は最大 +30 まで | いずれも設定可。回復上限後は体力回復なしで娯楽だけ可 |
| 休むの価値変動 | 体力 **30 以下**で休むと回復 **1.5 倍**。体力 **80 以上**なら回復 **0**（ダラダラ判定） | 「疲れてるときに休むのが正解」をルール化。閾値は設定可 |
| 睡眠による回復率 | 「寝る」宣言→起床時に睡眠時間を 1 タップ申告：7h 以上 100% / 6〜7h 85% / 6h 未満 70% | 設定の回復率はこの申告がない日のデフォルト。将来は Health Connect で自動化（11.1） |
| 体力 0 のとき | レッスン選択肢が出ず「休む」か「寝る（今日を終える）」のみ | 無理させない |

### 3.3 アクション（レッスン）テンプレート

ユーザーが登録する。初回起動時にプリセットを入れる。

```
Action {
  id, name, category(健康/趣味/自己実現),
  durationMin(15/30/60), staminaCost(10/20/30),
  baseGain(5/12/25),            // 時間に比例
  weight(出現確率の重み, 1〜5),
  timeWindow(朝/昼/夜/いつでも), // その時間帯しか出ない
  enabled
}
```

**3 択の生成ルール**

1. 体力が足りるアクションだけ候補にする。
2. カテゴリが偏らないように、今日まだやってないカテゴリを優先。
   さらに中期目標（第 12 章）で**遅れている軸**があれば、その軸のアクションの重みを ×2（最大 ×3）する。
3. 重みで 2 枚引く。15% で片方が **SP レッスン**（獲得 1.5 倍、カードが光る）。
4. 3 枚目は常に「休む」。ただし当日の娯楽上限に達していたら「休む」は「体力回復なしの娯楽（N 分）」表記になる。
5. 「引き直し」は 1 日 2 回まで。

### 3.4 バフ・ストリーク

| 状態 | 条件 | 効果 |
|---|---|---|
| 好調 | 2 日連続でレッスン 1 回以上 | 獲得 +10% |
| 絶好調 | 5 日連続 | 獲得 +25% |
| 不調 | 前日レッスン 0 回 | 翌日の最初の 1 回だけ獲得 +30%（復帰ボーナス、罰則にはしない） |
| 週のお題 | 毎週月曜に自動で 1 軸がテーマになる（例「今週は健康週」）。中期目標で遅れている軸があればそれを優先 | その軸の獲得 +20%。3 択カードに「お題」バッジ |

「オフ日」（13.3）を宣言した日はストリークの計算から除外する（切れない）。

### 3.5 レッスン実行

- 選択 → タイマー画面（Compose、前面通知にも残り時間表示）。
- 途中で「中断」可：経過時間に比例した獲得（最低 50%）。体力は全額消費。
- 完了 → 結果演出（獲得量ポップ）→ ホームへ。
- タイマー中は対象娯楽アプリは引き続きブロック（開くと「レッスン中！」画面）。開いた回数は「脱線」として記録し、終了時の自己申告（3.8）で確認する。

### 3.6 休む（娯楽）

- 許可時間：**60 分**がデフォルト。3 択画面で 30 分 / 60 分 を選べる（設定で候補を変更可）。
- 許可中は対象アプリを通す。終了時に再び 3 択割り込み（「もう少し休む」も選べるが回復はしない）。
- 休む回数・時間はレポートに出す（責めるトーンにはしない）。

### 3.7 週次評価（試験）

週の合計獲得量（3 軸合計）でランク判定。閾値は設定可、初期値：

| ランク | 週の合計獲得 |
|---|---|
| S | 400 以上 |
| A | 280 〜 |
| B | 180 〜 |
| C | 100 〜 |
| D | それ未満 |

加えて「最も伸びた軸」「レッスン回数」「娯楽時間」「連続日数」を併記。

### 3.8 レッスン失敗（自己申告）

学マスにはない要素だが「正直に申告できる」ほうが続くので入れる。

**申告のタイミング**

- レッスン完了画面に「ちゃんとできた」「微妙だった」「失敗した…」の 3 ボタン。
- 脱線（3.5）が 1 回以上検知されていた場合は、デフォルト選択を「微妙だった」にして聞く。
- タイマー終了を待たず途中で「失敗した…」も押せる。

**理由（複数選択 + 任意メモ）**

隠れて YouTube 見てた / 寝落ち / 集中できなかった / 別のことしてた / 体調悪かった / その他

**効果**

| 結果 | 獲得 | 体力 | ストリーク |
|---|---|---|---|
| ちゃんとできた | 100%（バフ・SP 込み） | 全額消費 | 継続 |
| 微妙だった | 50% | 全額消費 | 継続 |
| 失敗した… | **0%** | **半額消費**（やろうとはした） | **継続**（挑戦したので切れない） |

- 失敗を申告すると「正直申告」が 1 回カウントされ、**次のレッスン 1 回だけ獲得 +10%**（正直ボーナス）。嘘をつく動機を消す。
- 「隠れて YouTube 見てた」を選んだ場合は、その時間を娯楽ログにも自動で入れる（娯楽時間に反映。体力回復は適用しない）。

**レッスン外の自己申告**

- 後付け記録（13.1）から「娯楽してた」も申告できる（PC やテレビで見た分など、割り込みが検知できないもの）。娯楽時間に加算し、体力回復は通常ルールで適用。正直に言った方が得になるようにする。

**レポートへの反映**

- 日次：失敗・微妙の件数と理由。
- 週次：**脱線率**（失敗＋微妙 ÷ 全レッスン）と理由の内訳。コメント文は責めない（「来週は寝る前のレッスンを減らしてみる？」など提案口調）。
- 中期目標の逆算（12.3）では、失敗分は獲得 0 として扱うだけで追加ペナルティはなし。

## 4. 割り込み（娯楽アプリ検知）

### 4.1 方式

**採用：AccessibilityService**（アプリブロッカー系の定番）

- `TYPE_WINDOW_STATE_CHANGED` でフォアグラウンドのパッケージ名を取得。
- ブロック対象かつ「許可中でない」なら、フルスクリーンの `InterruptActivity` を起動
  （`FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TOP`）。
- 自分専用アプリなので Play ストアの Accessibility ポリシーは気にしない。

**ローカル完結・セキュリティ方針**（権限 ON の前提条件）

- マニフェストに `INTERNET` 権限を**付けない**（通信できないアプリにする）。AI 連携（第 11 章）を入れるときだけ明示的に追加する。
- AccessibilityService は `packageNames` を対象アプリに限定し、取得するのは **パッケージ名のみ**。画面内テキスト・入力内容は読まない（`canRetrieveWindowContent=false`）。
- データは Room / DataStore のアプリ専用領域のみ。バックアップは `allowBackup=false`。エクスポートはユーザー操作時のみ。
- ソースは全部このリポジトリにあり、自分でビルドして入れる。

**代替（不採用、理由付き）**

- `UsageStatsManager` ポーリング＋オーバーレイ：遅延・電池消費・Android 14+ での制約が多い。
- Digital Wellbeing / Focus Mode 連携：外部からは制御できない。

### 4.2 対象アプリ

- 設定画面でインストール済みアプリ一覧から選択（デフォルト候補：YouTube、X、TikTok、Instagram、ゲーム、ブラウザは任意）。
- 「静かな時間」（例 22:00〜翌 5:00 は割り込まない）を設定可。
- 緊急バイパス：3 択画面を 3 秒長押しで 5 分だけ通す（1 日 3 回まで。レポートに記録）。

### 4.3 必要権限

- アクセシビリティサービス（ユーザーが設定画面で手動 ON）
- 通知（Android 13+）
- 正確なアラーム（`SCHEDULE_EXACT_ALARM`、レポート生成・娯楽タイマー用）
- バッテリー最適化の除外を促す（サービスが殺されないように）
- サービスの死活監視は 13.5 を参照。

## 5. レポート

### 5.1 日次レポート（毎日 日付境界 5:00 に自動生成、通知）

- 3 軸の獲得量と当日終了時の累計
- 体力の推移（簡易折れ線）
- レッスン一覧（時間・カテゴリ）／ 娯楽の回数・時間
- 連続日数・バフ状態
- 中期目標の進捗と「今日の不足分」（第 12 章の逆算結果の要約）
- レッスン失敗・微妙の件数と理由（3.8）
- 割り込みが動いていなかった時間帯（13.5）。オフ日なら「オフ日」表記
- 一言コメント（テンプレ文からランダム。プロデューサー口調）

### 5.2 週次レポート（週の最終日の日付境界に自動生成、通知）

中期目標が有効なら、週次レポートが**中間試験**になる（第 12 章）。

- ランク（S〜D）と演出
- 3 軸の週間獲得と前週比
- 日別のレッスン回数・娯楽時間の棒グラフ
- 「最も伸びた軸」「一番やったアクション」
- 脱線率と理由の内訳（3.8）、週のお題の達成状況
- 中間試験の結果（軸ごとの合否・不足・来週の必要ペース）
- 翌週への一言

### 5.3 生成方法

- `WorkManager` の定期ジョブ ＋ 起動時のバックフィル（端末が落ちていた日も後から生成）。
- 「寝る」宣言（13.2）をした場合はその時点で日次レポートを即生成する。
- レポートは Room に保存し、履歴画面でいつでも見返せる。
- エクスポート：Markdown / CSV を端末ストレージに出力（任意）。

## 11. 将来拡張（M6 以降、任意）

### 11.1 Health Connect 連携（Pixel の歩数・睡眠）

- **歩数**：Health Connect の `StepsRecord` を日次で読み、1,000 歩ごとに健康 +1（1 日上限 +10）を自動加算。レッスンを選ばなくても「歩いた分」が反映される。
- **睡眠**：`SleepSessionRecord` の睡眠時間で翌日の体力回復率を自動調整（例：7h 以上 100%、6h 85%、5h 以下 70%）。手動設定の回復率より優先するかは設定で選べる。
- 権限は Health Connect の読み取りのみ。通信は不要なので `INTERNET` 権限なしのまま実装できる。

### 11.2 分身ちゃん（アバター）

- ホームに自分の分身キャラを置き、3 軸の累計やランクに応じて見た目・表情・称号が変わる。
- 画像は端末内の静的アセット（差分パーツ）。学マスのような「育てている感」を出す演出レイヤーで、ゲームロジックには影響しない。

### 11.3 AI 連携（褒めコメント・ストーリー生成）

- 日次・週次レポートの一言コメントを LLM API で生成（「分身ちゃんが褒めてくれる」「今週のストーリー」）。
- 送るデータはレポートの数値サマリのみ（アクション名・獲得・娯楽時間）。生データやアプリ利用履歴の詳細は送らない。
- このときだけ `INTERNET` 権限を追加し、API キーは端末内の暗号化ストレージ（EncryptedSharedPreferences）に保存。オフライン時はテンプレ文にフォールバック。
- どの API を使うかは着手時に決める。

## 12. 中期目標と試験（逆算）

学マスの中間試験・最終試験に相当。「この期間でここまで伸ばす」を宣言し、
アプリが定期的に**試験**を行って「目標に対して何が、どれだけ足りないか」を逆算して出す。

### 12.1 目標の定義

```
Goal {
  name            // 例「冬コミまでにイラスト本を出す」「体重 -3kg」
  startDate       // 作成日（または指定）
  deadline        // 期限。2〜12 週間を推奨（UI でプリセット 4 / 8 / 12 週）
  targets[]       // 下記 3 種を混在可
  status          // ACTIVE / PASSED / FAILED / ABANDONED
}

GoalTarget は 3 種類：
  AXIS          : 軸の獲得量   例「趣味 +300」「健康 +120」（期間内の獲得で判定）
  ACTION_COUNT  : アクション回数 例「イラスト制作 ×16 回」「筋トレ ×24 回」
  CHECKLIST     : 手動チェック  例「ネームを描き終える」「ポートフォリオ公開」
required = true のものは最終試験の合格条件。false は加点項目。
```

- 同時に有効な目標は **1 つ**（学マスの 1 プロデュース = 1 目標のイメージ）。終了後に次を作る。
- 目標テンプレを用意（「体づくり 8 週」「創作 1 本仕上げる 12 週」「資格勉強 4 週」）。数値は編集可。

### 12.2 試験のタイミング

| 種別 | タイミング | 内容 |
|---|---|---|
| **中間試験** | 毎週の週次レポート時（月曜 5:00） | 進捗率と必要ペースを判定。合否ではなく「順調 / 注意 / 危険」の 3 段階 |
| **最終試験** | deadline の翌日 5:00 | required ターゲットが全部達成で **合格**。ランク S〜D も併記 |
| **抜き打ち** | ホームの目標カードをタップした時 | いつでも現時点の逆算を表示（記録はしない） |

### 12.3 逆算ロジック

ターゲットごとに次を計算する。

```
remaining     = target - current                    // 不足量
daysLeft      = deadline - today
requiredPace  = remaining / daysLeft                 // 1 日あたり必要量
currentPace   = current / daysElapsed                // 今までの平均
projected     = current + currentPace * daysLeft     // このままいくと
judgement     = projected >= target ? 順調
              : projected >= target * 0.8 ? 注意
              : 危険
```

**不足分を「アクション回数」に翻訳する**（これが画面に出るメインの表示）

- AXIS ターゲットの remaining を、その軸の有効アクションの `baseGain` で割って
  「あと **イラスト制作（30 分）× 9 回** か **ゲーム制作（60 分）× 5 回**」のように 2〜3 パターン提示。
- バフ（好調 +10% など）は見込まない。SP も見込まない（出たらラッキー扱い）。
- ACTION_COUNT は単純に「あと N 回」、CHECKLIST は未チェック項目を列挙。

**体力の実現可能性チェック**

```
staminaPerDay   = maxStamina * recoveryRate + 娯楽回復の平均（直近 7 日実績）
neededStamina   = Σ(推奨アクションの staminaCost) / daysLeft
feasible        = neededStamina <= staminaPerDay * 0.8   // 2 割は余裕
```

- feasible でなければ「このペースは体力的に厳しい」と出し、
  (a) 期限を N 日延ばす、(b) 目標値を X に下げる、(c) 他の軸のターゲットを緩める、の 3 案を提示。選ぶと目標が更新される（履歴は残す）。

### 12.4 3 択・レポートへの反映

- 3 択生成時、judgement が「注意」の軸は重み ×2、「危険」の軸は ×3（第 3.3 章）。
- 「危険」の軸は 3 択カードに「試験対策」バッジを付ける。
- 日次レポートに「目標：あと 12 日。趣味 −48（イラスト制作 ×4 回分）」のような 1 行要約を入れる。
- 週次レポート＝中間試験。軸ごとの 順調/注意/危険、来週の必要ペース、推奨アクションを表示。

### 12.5 最終試験の結果

- required を全達成 → **合格**。演出（最小限：ランク表示＋獲得サマリ）。
- 未達 → **不合格**だが、達成率と「あと何が足りなかったか」を表示し、「同じ目標で再挑戦（期限リセット）」ボタンを出す。罰則はなし。
- 結果は ExamResult に保存し、目標画面の履歴から見返せる。

### 12.6 画面

- **目標画面**：目標名・期限・残日数、ターゲットごとの進捗バー（current / target）、判定バッジ、不足分の翻訳（推奨アクション）、体力の実現可能性、中間試験の履歴。
- **目標作成**：テンプレ選択 → 名前・期限 → ターゲット追加（軸 / アクション回数 / チェックリスト）→ 作成時点で逆算して「1 日あたりこれくらい」を見せてから確定。
- **試験結果**：中間 / 最終の結果カード。ホームの通知からも開ける。

## 13. 運用機能

### 13.1 後付け記録

- ホームと通知のアクションから「さっきやった」を開き、アクション・開始時刻（15 分刻み）・結果（3.8 の 3 択）を選んで記録。
- 体力消費・獲得・バフは通常のレッスンと同じ計算。`source = MANUAL` で区別し、レポートでは「手動」マークを付ける。
- 「娯楽してた」も同じ画面から申告（RestLog `SELF_REPORT`）。
- 記録できるのは当日と前日まで（日付境界基準）。それより前は編集不可にして数値の信頼性を守る。

### 13.2 「寝る」宣言

- ホームの「寝る」ボタン → その時点で日次レポート生成、翌朝の日付境界まで割り込み停止（娯楽は通る）。
- 翌日、最初にアプリを開いた／最初の割り込み時に「何時間寝た？」を 3 ボタンで聞く（6h 未満 / 6〜7h / 7h 以上）。回答で当日の回復率を決める（3.2）。未回答なら設定のデフォルト回復率。
- 寝る宣言をしなかった日は日付境界で通常生成。

### 13.3 オフ日宣言

- ホームの「今日はオフ」→ 当日は割り込み停止、ストリーク計算から除外、日次レポートは「オフ日」として簡略版。
- 体力は消費しないので翌日は通常回復。
- 連続オフは 2 日まで。3 日目は「本当にオフ？」と確認（禁止はしない）。回数は週次レポートに出す。

### 13.4 バックアップ / 復元

- 設定から **JSON フルバックアップ**（全テーブル＋設定）を端末ストレージの任意の場所に書き出し（`ACTION_CREATE_DOCUMENT`）。
- 復元は同じファイルを選んで全置換（確認ダイアログ付き）。スキーマバージョンを埋め込み、古い形式は移行する。
- 自動バックアップ：週次レポート生成時にアプリ専用外部ストレージへ直近 4 世代を保存（端末が生きていれば再インストール時に拾える）。
- 通信は発生しない。クラウド同期はやらない。

### 13.5 割り込みサービスの死活監視

- AccessibilityService の `onServiceConnected` / `onUnbind` で稼働区間を `ServiceGap` に記録。
- 15 分ごとの軽量チェック（WorkManager）で「設定上は有効なのに接続されていない」を検知したら通知「割り込みが止まってるよ。設定から再 ON して」。
- 止まっていた区間はレポートに「監視なし」として表示し、娯楽時間の集計からは除外（ズルではなく不具合だと分かるように）。
- Pixel の「使っていないアプリの権限を削除」で切れることがあるので、設定画面にその OFF 手順も載せる。

### 13.6 ホーム画面ウィジェット

- Glance（Jetpack）で実装。サイズ 4×2：体力バー、3 軸の今日の獲得、ストリーク、目標の残日数。
- タップで 3 択画面を直接開く。（Android のアプリウィジェットは長押しをランチャーが取るため、長押しショートカットは置けない。「寝る」「オフ」はホーム画面のボタンから。）
- 更新タイミング：レッスン完了・休む終了・日付境界・寝る宣言のとき。
