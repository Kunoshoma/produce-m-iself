# produce-m-iself 仕様書（ドラフト v0.1）

> 学園アイドルマスター（学マス）のプロデュース感覚で、**自分自身をプロデュースする** Android アプリ。
> 娯楽アプリ（YouTube・ゲームなど）を開く前に割り込んで「3択」を出し、
> レッスン（自己成長）か「休む」（娯楽）かを選ばせる。選択結果はステータスと体力に反映され、
> 毎日・毎週レポートを自動生成する。
>
> - 利用者：自分だけ（外部リリースなし / GitHub 非公開）
> - 状態：**仕様すり合わせ中**。末尾の「決めたいこと」に答えてもらったら実装開始。

---

## 1. コンセプト

| 学マス | このアプリ |
|---|---|
| アイドル | 自分 |
| プロデューサー | アプリ（＋自分） |
| レッスン（Vo / Da / Vi） | 自己成長アクション（3カテゴリ） |
| 体力 | 1日の行動エネルギー（アクションで消費、休む・睡眠で回復） |
| 休む / お出かけ | 娯楽（YouTube・ゲーム等）。体力は回復するがステータスは上がらない |
| ターン | 1日 |
| 中間 / 最終試験 | 週次レポートで評価ランク（S〜D）判定 |
| SP レッスン | ランダムに出現する獲得量 1.5 倍のアクション |
| 好調 / 絶好調 | 連続達成（ストリーク）による獲得量バフ |

**ゲームデザインの軸**

1. 「やらなきゃ」ではなく「どれ選ぶ？」。常に 3 択で、娯楽も正当な選択肢（休む）として用意する。
2. 体力に上限がある → 1 日に詰め込めない。無理すると翌日に響く。
3. 成長が数値とグラフで見える。レポートが毎日・毎週勝手に届く。

## 2. コアループ

```
[娯楽アプリを開こうとする]
        │ 割り込み（AccessibilityService で検知 → フルスクリーン表示）
        ▼
[3択画面] ── 2枚：レッスン（カテゴリ別・体力コスト・獲得量表示）
          └─ 1枚：休む（娯楽を N 分だけ許可・体力小回復）
        │
   ┌────┴─────┐
   ▼          ▼
[レッスン]   [休む]
 タイマー開始   娯楽アプリへ戻す
 終了時に完了   N 分後に再び割り込み
 ステータス↑    体力↑（上限あり）
 体力↓
        │
        ▼
[その日の終わり] 日次レポート自動生成 → 通知
[週の終わり]     週次レポート自動生成（ランク判定）→ 通知
```

割り込みなしでもホーム画面から自分で 3 択を引ける（「プロデュース開始」ボタン）。

## 3. ゲームシステム

### 3.1 ステータス（3 軸、名前は変更可）

| 学マス | デフォルト名 | 例 |
|---|---|---|
| ボーカル | **知性**（学び） | 読書、勉強、資格、コーディング学習 |
| ダンス | **フィジカル**（カラダ） | 筋トレ、ランニング、ストレッチ、散歩 |
| ビジュアル | **暮らし**（生活力） | 掃除、料理、身だしなみ、人付き合い、家事 |

- 各ステータスは 0 から積み上げ（上限なし、学マスの 1500 上限みたいなキャップは設けない）。
- 週次ランクは「その週の獲得量」で判定するので、途中から始めても不利にならない。

### 3.2 体力

| 項目 | デフォルト | 備考 |
|---|---|---|
| 最大体力 | 100 | 設定で変更可 |
| 1日の開始時 | 全回復（朝 5:00 を日付境界とする） | 睡眠記録なし版。将来ヘルスコネクト連携で睡眠時間に応じた回復も検討 |
| レッスン消費 | アクションごとに設定（小 10 / 中 20 / 大 30） | 目安：15分=小、30分=中、60分=大 |
| 休む（娯楽）回復 | +5 / 15 分、1 日の娯楽回復は最大 +30 まで | ダラダラ防止。回復上限後は体力回復なしで娯楽だけ可 |
| 体力 0 のとき | レッスン選択肢が出ず「休む」か「寝る（今日を終える）」のみ | 無理させない |

### 3.3 アクション（レッスン）テンプレート

ユーザーが登録する。初回起動時にプリセットを入れる。

```
Action {
  id, name, category(知性/フィジカル/暮らし),
  durationMin(15/30/60), staminaCost(10/20/30),
  baseGain(5/12/25),            // 時間に比例
  weight(出現確率の重み, 1〜5),
  timeWindow(朝/昼/夜/いつでも), // その時間帯しか出ない
  enabled
}
```

**3 択の生成ルール**

1. 体力が足りるアクションだけ候補にする。
2. カテゴリが偏らないように、今日まだやってないカテゴリを優先。
3. 重みで 2 枚引く。15% で片方が **SP レッスン**（獲得 1.5 倍、カードが光る）。
4. 3 枚目は常に「休む」。ただし当日の娯楽上限に達していたら「休む」は「体力回復なしの娯楽（N 分）」表記になる。
5. 「引き直し」は 1 日 2 回まで。

### 3.4 バフ・ストリーク

| 状態 | 条件 | 効果 |
|---|---|---|
| 好調 | 2 日連続でレッスン 1 回以上 | 獲得 +10% |
| 絶好調 | 5 日連続 | 獲得 +25% |
| 不調 | 前日レッスン 0 回 | 翌日の最初の 1 回だけ獲得 +30%（復帰ボーナス、罰則にはしない） |

### 3.5 レッスン実行

- 選択 → タイマー画面（Compose、前面通知にも残り時間表示）。
- 途中で「中断」可：経過時間に比例した獲得（最低 50%）。体力は全額消費。
- 完了 → 結果演出（獲得量ポップ）→ ホームへ。
- タイマー中は対象娯楽アプリは引き続きブロック（開くと「レッスン中！」画面）。

### 3.6 休む（娯楽）

- 許可時間：15 分 / 30 分 の 2 択（設定で変更可）。
- 許可中は対象アプリを通す。終了時に再び 3 択割り込み（「もう少し休む」も選べるが回復はしない）。
- 休む回数・時間はレポートに出す（責めるトーンにはしない）。

### 3.7 週次評価（試験）

週の合計獲得量（3 軸合計）でランク判定。閾値は設定可、初期値：

| ランク | 週の合計獲得 |
|---|---|
| S | 400 以上 |
| A | 280 〜 |
| B | 180 〜 |
| C | 100 〜 |
| D | それ未満 |

加えて「最も伸びた軸」「レッスン回数」「娯楽時間」「連続日数」を併記。

## 4. 割り込み（娯楽アプリ検知）

### 4.1 方式

**採用：AccessibilityService**（アプリブロッカー系の定番）

- `TYPE_WINDOW_STATE_CHANGED` でフォアグラウンドのパッケージ名を取得。
- ブロック対象かつ「許可中でない」なら、フルスクリーンの `InterruptActivity` を起動
  （`FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TOP`）。
- 自分専用アプリなので Play ストアの Accessibility ポリシーは気にしない。

**代替（不採用、理由付き）**

- `UsageStatsManager` ポーリング＋オーバーレイ：遅延・電池消費・Android 14+ での制約が多い。
- Digital Wellbeing / Focus Mode 連携：外部からは制御できない。

### 4.2 対象アプリ

- 設定画面でインストール済みアプリ一覧から選択（デフォルト候補：YouTube、X、TikTok、Instagram、ゲーム）。
- 「静かな時間」（例 22:00〜翌 5:00 は割り込まない）を設定可。
- 緊急バイパス：3 択画面を 3 秒長押しで 5 分だけ通す（1 日 3 回まで。レポートに記録）。

### 4.3 必要権限

- アクセシビリティサービス（ユーザーが設定画面で手動 ON）
- 通知（Android 13+）
- 正確なアラーム（`SCHEDULE_EXACT_ALARM`、レポート生成・娯楽タイマー用）
- バッテリー最適化の除外を促す（サービスが殺されないように）

## 5. レポート

### 5.1 日次レポート（毎日 日付境界 5:00 に自動生成、通知）

- 3 軸の獲得量と当日終了時の累計
- 体力の推移（簡易折れ線）
- レッスン一覧（時間・カテゴリ）／ 娯楽の回数・時間
- 連続日数・バフ状態
- 一言コメント（テンプレ文からランダム。プロデューサー口調）

### 5.2 週次レポート（週の最終日の日付境界に自動生成、通知）

- ランク（S〜D）と演出
- 3 軸の週間獲得と前週比
- 日別のレッスン回数・娯楽時間の棒グラフ
- 「最も伸びた軸」「一番やったアクション」
- 翌週への一言

### 5.3 生成方法

- `WorkManager` の定期ジョブ ＋ 起動時のバックフィル（端末が落ちていた日も後から生成）。
- レポートは Room に保存し、履歴画面でいつでも見返せる。
- エクスポート：Markdown / CSV を端末ストレージに出力（任意）。

## 7. 技術スタック

| 項目 | 選定 |
|---|---|
| 言語 / UI | Kotlin / Jetpack Compose (Material 3) |
| アーキテクチャ | MVVM + UseCase、単一モジュール（規模的に十分） |
| DI | Hilt |
| DB | Room |
| 設定 | DataStore (Preferences) |
| バックグラウンド | WorkManager（レポート）、AlarmManager（娯楽タイマー・日付境界） |
| 割り込み | AccessibilityService |
| グラフ | Vico（Compose 対応） |
| minSdk / targetSdk | 26 (Android 8.0) / 35 |
| ビルド・配布 | GitHub Actions で debug APK を Artifacts に出力 → 端末に sideload。署名は debug key でよい |
| バックエンド | なし（完全オフライン、データは端末内のみ） |

## 10. 決めたいこと（要回答）

1. **ステータス 3 軸の名前**：「知性 / フィジカル / 暮らし」でいい？ 変えたい名前ある？ 4 軸以上にしたい？
2. **体力の回復**：翌朝 5:00 に全回復（シンプル）でいい？ それとも睡眠時間連動（Health Connect）までやる？
3. **休む（娯楽）の許可時間**：15 分 / 30 分の 2 択で OK？ 1 日の娯楽回復上限 +30 は妥当？
4. **割り込み方式**：AccessibilityService の権限を自分の端末で ON にするのは OK？（機種・Android バージョンも教えて）
5. **週の区切り**：月曜始まり・日曜終わりでいい？ 日付境界 5:00 は OK？
6. **プリセットのアクション**：初期に入れておきたい具体的なタスク（例：「英語 30 分」「筋トレ 15 分」）を教えて。なければ汎用プリセットで始める。
7. **演出の濃さ**：キャラ（自分のアバター）やボイス風テキストはどこまで欲しい？ 最小（数値＋グラフ）か、学マス寄り（カード演出・コメント多め）か。
8. **開発環境**：Android Studio は手元にある？ APK は GitHub Actions からダウンロードして入れる運用で OK？
